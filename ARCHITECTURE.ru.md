# Архитектура

[English](ARCHITECTURE.md) · **Русский**

`frx2docx` конвертирует между форматами **абсолютного размещения** (шаблон
FastReport `.frx` и PDF) и **потоковыми** форматами (`.docx`, Markdown). Всё
устройство программы вытекает из этого несовпадения.

## Главная идея

FastReport ставит каждый объект по фиксированным `Left/Top/Width/Height`. Word
льёт абзацы один за другим. Общий знаменатель, который оба формата выражают
точно, — **таблица без видимых границ**: колонки берутся из уникальных
X-координат объектов бэнда, строки — из Y-координат, а объект занимает диапазон
ячеек со своими рамками, заливкой и выравниванием.

Эта сетка, которую строит `layout.gridify()`, — единственное промежуточное
представление прямого пути. Оба писателя, `.docx` и `.pdf`, рисуют *одну и ту
же* сетку, поэтому их выдачи согласованы по построению, а не по случайности.

Обратный путь использует другое промежуточное представление, `doctree`: на
входе уже документ, и его нужно заново обмерить и разложить.

```
                        прямой путь
.frx ──frxread──► прямоугольники ──layout──► сетка ──┬── docxwrite ──► .docx ──pdfconv──► .pdf
                                                     └── pdfwrite  ──► .pdf  (встроенный движок)

                        обратный путь
.docx ──docxread──┐
.pdf  ──pdfread ──┼──► doctree ──frxwrite──► .frx
.md   ──textread──┤
.txt  ────────────┘
```

## Технологии

| Задача | Решение | Почему так |
|---|---|---|
| Язык | Python ≥ 3.9 | В комплекте едет встроенный интерпретатор, пользователю ничего не ставить |
| `.docx` | `python-docx` плюс прямой `lxml` там, где библиотека не покрывает | Единственная обязательная зависимость |
| `.pdf` (запись) | свой писатель поверх `zlib` | Снимает требование Word/LibreOffice; CID-шрифты Identity-H дают корректную кириллицу |
| `.pdf` (чтение) | свой парсер | Готового читателя PDF на чистом Python без зависимостей нет; заодно `verify_layout` перестал требовать `poppler` |
| Шрифты | свой разбор TrueType | Нужен и для переноса строк (прямой путь), и для встраивания с подмножеством (PDF) |
| Запасные начертания | Liberation (SIL OFL 1.1) | Метрически совместимы с Arial / Times New Roman / Courier New, поэтому подмена не переверстывает страницу |
| Штрихкоды | свои кодировщики, `qrcode` необязателен | Code 128 / EAN / Code 39 / ITF — это пара таблиц; QR — нет |
| Картинки | свой разбор PNG/JPEG/BMP | Чтобы не тянуть Pillow |
| Тесты | `unittest` | Есть в стандартной библиотеке, поэтому их запускает и встроенный интерпретатор |

## Модули

### Общие

- **`common.py`** — единицы (`1 unit = 1/96 дюйма = 15 dxa = 0,75 pt`), разбор
  *и* сборка цветов, шрифтов, рамок и полей, подмножество `HtmlTags` в обе
  стороны. Все остальные модули говорят в этих единицах.
- **`fonts.py`** — находит файлы TrueType по семейству и начертанию — сначала
  системные, затем свою папку `fonts/` (внутри `.exe`, если собран), — читает
  `head`/`hhea`/`hmtx`/`cmap`/`OS/2`/`post`, меряет строки, переносит их
  и собирает **подмножество глифов** для встраивания. Подмножество сохраняет
  исходную нумерацию глифов (у выброшенных — пустые записи в `loca`), поэтому
  PDF адресует глифы напрямую через `CIDToGIDMap /Identity`. Одно это решение
  уменьшило готовые PDF с ~1,9 МБ до ~150 КБ.
  В комплекте едут Liberation Sans/Serif/Mono (SIL OFL 1.1) — они выбраны за
  метрическую совместимость с Arial, Times New Roman и Courier New: неизвестное
  семейство заменяется ближайшим из трёх, и переносы строк не съезжают.
  Системный шрифт всегда в приоритете, поэтому шаблон, просящий Arial, на
  машине с Arial получает именно его.
- **`rtf.py`** — RTF в обе стороны, с таблицами шрифтов и цветов, стеком групп
  и обработкой `\uN`. Используется для `RichObject` на выходе и доступен на
  обратном пути.
- **`barcode.py`** — Code 128 (автовыбор набора B/C), EAN-13/8, Code 39,
  Interleaved 2 of 5 и самодельный писатель PNG, чтобы не нужна была ни одна
  графическая библиотека.

### Прямой путь

- **`frxread.py`** — разбирает XML (в любой объявленной кодировке) в плоский
  список прямоугольников. У каждого типа объекта своя небольшая функция:
  `TextObject`, `TableObject` (с `ColSpan`/`RowSpan` и строками, где перекрытые
  ячейки опущены), `RichObject`, `PictureObject`, `BarcodeObject`,
  `CheckBoxObject`, `LineObject`, `ShapeObject`. Бэнды раскладываются на тело,
  верхний и нижний колонтитул; страницы с `Visible="false"` пропускаются — их
  не печатает и сам FastReport.
- **`layout.py`** — построение сетки. Здесь же решаются две беды, которые есть
  в любом настоящем шаблоне: подписи в дизайнере шире своего текста и налезают
  на соседей (`clip_overlaps`), а часть объектов лежит целиком поверх других
  (`extract_floats` выносит их в отдельную строку). Крупные пустые промежутки
  становятся блоками `spacer`, а не пустыми строками таблицы.
- **`docxwrite.py`** — сетка → `.docx`. Неочевидные места:
  - У пустых ячеек знак абзаца кеглем 1 pt, иначе Word держит высоту каждой
    строки по кеглю стиля `Normal` и страница потихоньку раздувается.
  - `PageHeaderBand`/`PageFooterBand` становятся настоящими колонтитулами: поле
    страницы увеличивается ровно на высоту бэнда, а `header_distance` /
    `footer_distance` выставляются в исходное поле — тогда тело сохраняет ту
    высоту, которую ему дал FastReport.
  - `[Page]` / `[TotalPages]` превращаются в поля `w:fldSimple`.
  - Водяной знак — VML `v:rect` с надписью, а не WordArt `v:textpath`: второй
    пишет сам Word, но ряд его сборок отказывается его печатать при экспорте.
- **`pdfwrite.py`** — сетка → `.pdf` напрямую. Текст раскладывается теми же
  метриками, которыми меряется; выключка по формату расставляет слова
  поштучно (`Tw` не работает с двухбайтовыми строками Identity-H); строки, не
  влезающие в страницу, рвутся по границам строк, а строка выше целой страницы
  разрывается построчно, чтобы длинные абзацы перетекали на следующий лист.
  Проход рендера двойной: первый считает страницы, чтобы во втором был известен
  `[TotalPages]`.
- **`pdfconv.py`** — внешний путь: одна сессия Word (pywin32/comtypes, запасной
  вариант — COM через PowerShell) или один запуск LibreOffice на всю пачку.
  Возвращает, что именно удалось, чтобы вызывающий код мог откатиться на
  встроенный движок по каждому файлу отдельно.

### Обратный путь

- **`doctree.py`** — модель документа: секции с геометрией страницы и блоки
  (`p`, `table`, `image`, `space`, `abs`). `abs` — лазейка для источников,
  которые уже знают свои координаты, то есть для PDF.
- **`docxread.py`** — `.docx` → `doctree`. Идёт по телу документа по порядку,
  чтобы абзацы и таблицы сохранили последовательность; разворачивает цепочку
  `styles.xml` (`basedOn` + `docDefaults`), поэтому стилевые заголовки не
  теряются; восстанавливает `rowspan` из `vMerge`; не заходит внутрь `w:pict`,
  чтобы водяной знак не вернулся текстом в тело.
- **`pdfparse.py`** — объектный слой PDF. Он сознательно **не читает таблицу
  ксреф**: вместо этого перебирает по файлу все вхождения `N G obj` и
  разворачивает потоки объектов. Одним кодом покрываются линеаризованные файлы,
  сжатые ксреф-таблицы PDF 1.5+ и битые документы. Фильтры: Flate, LZW,
  ASCIIHex, ASCII85, RunLength и предикторы PNG/TIFF.
- **`pdfread.py`** — шрифты (CMap `ToUnicode`, `Encoding` + `Differences`,
  массивы `W` для CID) и интерпретатор содержимого, который ведёт графическую
  и текстовую матрицы. Word выдаёт отдельный оператор показа на каждую пару
  кернинга, поэтому результат пересобирается: прогоны глифов → строки →
  сегменты (режутся по настоящим пробелам, так выживают колонки) → абзацы
  (подряд идущие односегментные строки с общим левым краем, первой строке
  разрешена красная строка). Обводки и тонкие закрашенные прямоугольники
  одинаково становятся линейками, а соседние куски одной рамки склеиваются
  обратно.
- **`textread.py`** — Markdown и обычный текст.
- **`frxwrite.py`** — `doctree` → `.frx`. Меряет каждый абзац через
  `fonts.wrap`, чтобы узнать его высоту, складывает блоки сверху вниз и пишет
  `TextObject` / `TableObject` / `PictureObject` внутрь
  `PageHeaderBand` / `DataBand` / `PageFooterBand`. Неоднородное оформление
  внутри абзаца пишется как `TextRenderType="HtmlTags"`.

### Точки входа

- **`frx2docx.py`** — тонкий запускатель: добавляет локальные папки библиотек
  в `sys.path`, проверяет `python-docx`, зовёт `frxkit.cli.main`.
- **`frxkit/cli.py`** — разбор аргументов, раскрытие входа и логика пачек:
  сначала делаются все `.docx`, потом PDF собирается одним запуском внешнего
  конвертера, а всё, что внешний конвертер не осилил, пофайлово откатывается на
  встроенный движок.
- **`verify_layout.py`** — регрессионная проверка вёрстки, см. ниже.

## Решения, о которых стоит знать

**Почему PDF не всегда делается из `.docx`?** Делается — когда есть Word или
LibreOffice: их перенос строк и есть эталон. Встроенный движок нужен, чтобы
обещание «без установки» держалось и на машине, где нет ни того, ни другого.
Поскольку оба рендерера едят одну и ту же сетку, выдачи остаются близкими: на
эталонном наборе встроенный движок даёт то же число страниц, что и Word, для
большинства шаблонов, а положение текста совпадает с шаблоном в пределах
0,55 мм.

**Почему объекты PDF ищутся перебором, а не по ксреф?** Потому что ксреф — как
раз то место, которое чаще всего оказывается неверным, упакованным в поток или
продублированным инкрементальными правками. Перебор стоит одного прохода по
файлу и снимает целый класс отказов.

**Почему нумерация глифов сохраняется при подмножестве?** Перенумерация
потребовала бы потока `CIDToGIDMap` и переписывания всех ссылок в составных
глифах. Сохранить нумерацию и опустошить неиспользуемые ячейки `loca` — это
несколько строк, `CIDToGIDMap /Identity` остаётся, а остаточная таблица `loca`
стоит пары килобайт.

**Почему скрытые страницы пропускаются по умолчанию?** FastReport не печатает
`ReportPage` с `Visible="false"`. В шаблонах так хранят варианты, которые
включает скрипт. Переносить их все — вводить в заблуждение; ключ `--all-pages`
есть на случай, когда посмотреть их всё-таки нужно.

**Где конвертер честен о своих границах.** Состояние, которым управляет скрипт;
штрихкоды, содержимое которых задано выражением; картинки, подставляемые при
печати; неподдержанные типы объектов — на каждое печатается именное
предупреждение. Правило одно: ничто не исчезает молча.

## Проверка

`verify_layout.py` — регрессионный тест вёрстки. Он берёт шаблон и полученный
из него PDF и для каждой статической надписи с выключкой влево сравнивает
расстояние от левого края страницы: ожидаемое — по координатам FastReport,
фактическое — по положению глифов в PDF. Надписи по центру, по правому краю, с
подстановками и с отступом первой строки исключаются: их не с чем сравнивать.

На эталонном наборе из 11 боевых шаблонов медиана сдвига — 0,01 мм через Word
и 0,53 мм через встроенный движок, за порогом 3 мм нет ничего.

`tests/test_frxkit.py` закрывает остальное: 53 теста на разборщики, RTF,
штрихкоды, метрики и подмножества шрифтов, табличную раскладку, лексер PDF и
CMap, а также round-trip в обе стороны.

  docxwrite.py        сетка → .docx

  doctree.py          модель документа для обратного пути
